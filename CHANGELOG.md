# Changelog

All notable changes to farmout are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

## [0.1.0] - unreleased

### Added

- **A command line:** `farmout` (`pip install .`, or `python3 server.py <command>`), with `--json` and exit codes on every command, and prompts from stdin (`git diff | farmout ask "..."`).
- **Sessions:** `farmout run <worker>` starts a named conversation that the worker really remembers, resumed through each CLI's own session id (`claude --resume`, `codex exec resume`, `copilot --session-id`, `agy --conversation`; farmout keeps `api` history itself). `send` queues messages to a busy session, `--attach` hands over another session's reply, `fork` branches a conversation (natively for Claude, with the transcript for the others), and `ls`, `log`, `attach`, `wait`, `stop` and `rm` manage them. Each session's runner is its own process, so `stop` stops exactly one session and its worker.
- **`farmout review`**: every worker reviews your uncommitted, staged (`--staged`) or branch (`--base`) changes in parallel; findings are merged across models with agreement counts, findings that cite a missing file or line are dropped, and `--min-agree` / `--fail-on` make it a gate.
- **`farmout race`** (every worker in its own worktree; `--test` picks the winner, `--apply` lands it), **`farmout ask`**, and **`diff`** / **`apply`** / **`apply --pr`** for isolated sessions.
- **Pipelines:** stages in `.toml` or `.json` files (`<repo>/.farmout/pipelines/`, `~/.config/farmout/pipelines/`) that start when the previous one ends, with `{stage}` / `{stage.patch}` / `{args}` placeholders, gates (`tests`, `agree >= 2`, `high == 0`, `contains "..."`), `on = failure | always`, `foreach` fan-out, approval steps, background runs, stop and resume. Built in: `fix` (review, fix what 2+ models agree on, review the fix) and `spec` (requirements, design, tasks, parallel build, check).
- **Settings** in `~/.config/farmout/settings` and `<repo>/.farmout/settings`: which workers may see a repository, no writes, no web access, a fallback order, a timeout. Neither file can loosen the other, and settings are always read from the main working tree.
- **Usage limits and stats:** a worker that hits its subscription limit is left alone until it resets, and with a fallback order the task moves to the next worker; `farmout stats` shows each subscription's runs, failures, limits, time and tokens.
- **`farmout hook install`**: a pre-commit (or `--pre-push`) hook that blocks a commit when 2+ models flag a high-severity problem.
- **`.farmoutinclude`**: ignored files (such as `.env`) copied into isolated worktrees, never into patches.
- **MCP tools** `send`, `sessions` and `pipeline`, next to `delegate` (which gains `effort`).
- **The official MCP Registry:** `server.json` (`io.github.JayPokale/farmout`, run as `uvx farmout mcp`); each release is listed there by the release workflow once PyPI has it.
- **`farmout fix-pr --dry-run`** prints the brief the workers would get from a pull request's feedback, and starts nothing.
- **Model lanes in `farmout bench`:** `-w claude:opus,claude:sonnet,codex` (or `copilot:<model>` for a model your Copilot plan has enabled) names a model per lane, and one worker on several models compares them side by side; the card names each model. Cards also name the models farmout picks by default (Gemini Flash low, Claude Sonnet).
- **One subscription fills several lanes** in `ask`, `review`, `race`, `fix-pr`, `debate` and pipeline stages: `-w claude:opus,claude:sonnet`, or `-w codex,codex` for two runs of one model (labelled `codex#2`). Results and sessions are kept per lane.
- **`farmout bench --apply`** makes the measured winners this repository's defaults: each compared worker's best model (`models`) and a best-first `fallback` order in `.farmout/settings.json` (ties go to the quicker lane). `--apply --last` applies the newest saved run without spending anything.
- **A conversation can change model or worker:** `farmout send <session> --model opus` keeps the conversation and changes the model; `-w codex[:model]` moves it to another worker, which gets the turns so far as a file. The MCP `send` tool takes `worker` / `model` for an existing session too.
- **Fallback by default:** with no order set, a task whose worker is at a usage limit or logged out goes to the next ready worker (never `api`, never one the repository forbids); `fallback = []` or `--fallback ""` turns it off. Entries can name a model (`claude:sonnet` after `claude:opus`), limits are kept per model, and a limit in the middle of a conversation hands the turns so far to the next worker. Reviews never fall back, and with no `-w` they leave out workers known to be limited.
- **Logged out or subscription ended** (a 401, "Not logged in", an expired token) is handled like a limit: skipped for 30 minutes, shown by `status`, `stats` and `doctor`, with a log-in hint when nothing can take over.
- **Reset times** are read from more wordings: "try again in 4 days 2 hours", "retry in 32.5s", Unix and ISO times, and clock times with a weekday and time zone ("resets 3pm (Asia/Kolkata)").
- A **`models` setting** picks each worker's default model; `farmout run claude:opus` names one inline, and `run auto` follows model lanes in the fallback order. `farmout doctor` suggests what to do with one subscription.
- `farmout review --json` (and `bench`'s report) include each worker's raw reply, next to the parsed findings.
- **Bug-Finding Leaderboard tooling** (`bench/leaderboard.py`, in the repository): 41 recent real fixes from 10 well-known projects, each screened by hand and by two models, reviewed per lane (a worker on its default model or a named one, such as `claude:opus`), with resumable runs, a no-quota `check`, `rescore` after a parser fix, and a Markdown table, JSON and card from `render`.
- `--effort` for every worker (`--effort`, `--reasoning-effort`, `model_reasoning_effort`).
- **Skills:** `SKILL.md` folders (the format Claude Code, Codex and Copilot share) run on your workers with `farmout <skill>`, in ask, review or race mode, also as pipeline stages. `farmout skill add` installs from a folder, a git repository or a URL; remote skills that contain code are refused.
- **Hooks** on farmout's events (SessionStart, MessageReceived, TaskStart, TaskEnd, StageEnd, PipelineEnd): JSON on stdin; a TaskStart hook can rewrite or block the brief. A project's own hooks run only after `farmout trust`, pinned to the settings file's SHA-256. `redact = true` strips credentials from briefs and piped input.
- **The store** (`store/` in this repository): reviewed skills, hooks and tools, every file pinned by SHA-256 and checked on install; `farmout store ls|show|add|rm|update`, `farmout tool run`. First entries: security-review, test-gaps, notify, guard-secrets, prune.
- **`farmout bench`**: replays recent small bug fixes from your history in a scratch worktree and scores each worker on finding them. With no second Claude account it ranks your main Claude login too (on its quota, never from inside Claude Code), so the card shows Claude; `FARMOUT_CLAUDE_MAIN=1` makes that login a worker for every command.
- **`farmout ask --debate`**, **`farmout fix-pr`** (a pull request's review comments and failing checks become a race), **`farmout undo`**, **`farmout apply`** for several patches in order, **`farmout export`** (Markdown or HTML), **`farmout status --line`** and **`farmout ls --watch`**.
- **Plugin slash commands:** `/farmout:review` (every worker reviews your diff in parallel; Claude merges the findings with agreement counts and verifies each), `/farmout:race` (every worker attempts the same fix in its own git worktree; your tests pick the winner), `/farmout:ask` (one question to every worker, compared), `/farmout:setup` (which workers are ready).
- **`copilot` worker:** GitHub Copilot CLI, read-only through a tool allowlist (`--available-tools`), because `--allow-all-tools` would also auto-approve the user's MCP servers.
- **`isolate: true`** on a task: the worker writes in a private git worktree under `<repo>/.farmout/` (HEAD plus your uncommitted and untracked files, committed as a base), and the result names a patch with only its changes. In-repo paths in `files` and in the brief are rewritten to the worktree, patches are taken against the base commit (so a worker's own commits count), caches stay out of patches, and the directory is kept out of `git status` through the repository's local exclude file.
- **`background: true`** on `delegate`: returns the result paths at once so the head keeps working; each file appears when its task ends, then a `done` file. Shutdown still stops background workers.
- **`python3 server.py doctor`** shows which workers are ready and the exact step to enable each missing one; `doctor --live` sends each ready worker one tiny prompt and reports broken logins.
- **Read guard** (plugin hook): the first big read of a file in a session (more than 5 pages of a long PDF, or 500+ lines of a 200 KB+ file) is stopped once with advice to delegate; reading it again goes through. `FARMOUT_READ_GUARD=0` turns it off.
- **Claude Code plugin manifest:** `claude plugin install farmout --marketplace JayPokale/farmout`, with an icon.
- **Benchmarks** (`bench/`) with raw outputs: head tokens with and without delegation, and review recall and agreement on 23 planted bugs.
- **Other heads:** Codex CLI and Copilot CLI are tested as MCP clients.
- README demo (an animated replay of a real run), translations into Chinese, Japanese, Korean and Spanish, a FAQ, and a social preview image.
- Offline test suite (CI on Ubuntu and macOS, Python 3.9/3.12/3.14), a real-CLI smoke test (`tests/smoke.py [worker ...]`), a slash-command smoke test (`tests/plugin_smoke.sh`), and a tag-driven release workflow.
- Contributor docs, issue and PR templates, and a security policy.
- **A website** (`site/`, Next.js, deployed separately; not part of the Python package): install paths, the workers and their flags, replays of real `farmout review` and `farmout race` runs right after the hero, pipelines, the benchmarks and the safety model.
- **Live lanes:** while `review`, `race`, `ask`, `fix-pr` and `bench` run, a terminal shows one row per worker: working, then its findings, its test result or its failure, with the time. Only on a terminal; `--json`, pipes and the MCP server see nothing, `NO_COLOR` drops the colours and `FARMOUT_LIVE=0` the lanes.
- **Conversations are trees:** `farmout fork <session> --at N` branches off any turn (numbered along the whole conversation, so a turn from before a branch began branches off the session it came from), on any worker or model (`-w worker[:model]`, `--model`). Branches are named after their conversation (`cache-1`, `cache-2`), and `export` shows a branch's whole conversation, numbered from its first turn. `farmout tree` (`--here` for this project's) draws each conversation as a graph, every branch in a lane of its own off the turn it came from, as `git log --graph` draws branches.
- **`farmout ui`:** every conversation as that graph, full-screen in your terminal (curses, from Python itself): move with the arrow keys, `j`/`k` or the mouse, fold branches, read any turn beside the graph, find a question or words in an answer (`/`), continue from the newest turn (`c`), branch off any turn (`b`) or ask a question a different way (`e`), on any worker or model, start a new conversation (`n`), or stop a running one (`x`). A pasted message keeps its newlines, Ctrl+G writes one in your editor, and `o` opens a turn (`O` its whole conversation) in your pager. Answers show **bold** and `code` as styles and list items as hanging bullets; `y` copies a turn's answer (through `wl-copy`, `xclip`, `xsel` or `pbcopy`, else the terminal, over ssh too), `d` shows an isolated session's patch, `D` deletes a conversation or branch with the branches off it, `f` shows only this project's conversations, and answers you haven't read yet are tagged "new" and announced on the bottom line as they come in (`u` goes to the next one), and `R` sends a failed newest turn again. A worker at its usage limit or logged out shows at the bottom of the graph, until when, and in the message box before you send to it. Questions and answers are shown without escape sequences or control characters, so a worker's output can't rewrite your terminal. `farmout ui --web` serves the same in your browser, on 127.0.0.1 only, with a key made for each run that the page sends back in a header, so another site can't use it (no CORS, a strict Content-Security-Policy, Host and Origin checked).
- **Moved and renamed folders:** sessions remember where their folder sits in its git repository. After a rename or move, `send`, `fork`, the MCP `send` tool and `farmout ui` find it from anywhere in the same repository, isolated worktrees are re-linked (`git worktree repair`), and the worker's next message says where the folder went. `--here` continues in the current folder outside git, and `farmout ls` marks folders that are gone. If a CLI can't find its own conversation any more, the same worker gets the conversation so far as a file instead of failing.
- **A waiting row:** a foreground `farmout run`, `send` or `fork` shows the worker, a spinner and the seconds so far (and where a fallback sent the turn) while it waits, then the answer in its place.
- **`farmout bench --share`**: the scores as a post that fits on X, an image card (SVG, plus PNG when librsvg or ImageMagick is installed) and a one-click post link. Scores only: no repository name, file names or code.
- **`deepseek` worker (experimental):** DeepSeek Harness (`dsh headless --json`), read-only by default (`--permission-mode read-only --approval-policy never`), resumed with `--session-id`. The README also shows DeepSeek's API on the `api` worker and how to run farmout inside DeepSeek Harness as an MCP server.
- MCP server with a `delegate` tool, 4 workers, parallel execution, cancellation that kills the process group, timeouts, result files and an output cap.
- Read-only and write flags verified against agy 1.4.6, codex-cli 0.163.0 and Claude Code 2.1.323.
- Workers are auto-detected; no personal paths in the code.
- README, LICENSE (MIT) and .gitignore.

### Changed

- **farmout is a package now** (`farmout/`, standard library only); `server.py` stays the entry point for the plugin and MCP clients. Isolated worktrees moved to `<repo>/.farmout/worktrees/`, so `.farmout/settings` and `.farmout/pipelines` can be committed.
- **Renamed from modelmux to farmout**, because modelmux was taken on PyPI, npm, crates.io and Homebrew. The plugin, slash commands (`/farmout:review` and so on), MCP server, environment variables (`FARMOUT_*`), worktree folder (`.farmout/`) and branch prefix (`farmout/`) all use the new name.

### Fixed

- `farmout rm` (and `rm --idle`) stopped at the first session it couldn't remove; it now says why for that one, removes the rest, and exits with 1.
- A removal that failed partway (a file that wouldn't delete) left half a session that `farmout rm` could no longer see or retry. A session's folder now moves to the state folder's trash in one step before it's deleted, under the session's runner lock, and a session with messages waiting, or branches working in its worktree, isn't removed at all.
- `farmout doctor` said fallback was off when the repository's settings file couldn't be read; it says the settings can't be read, and why.
- A Claude login folder with nothing in it (logged out) first reads as "no conversation found" on a resume; the turn's notes said "claude couldn't find its own conversation" before the real reason. They now say only that claude isn't logged in, and where the turn went.
- `farmout tree` and `ui` drew a row a column short when a question or answer held an emoji with a variation selector (⚠️), a zero-width joiner or an enclosing mark, pushing the right border in; they also drop bidirectional overrides now.
- `farmout ui` without `TERM`, with one the system doesn't know, or on a "dumb" terminal printed a curses traceback or scribbled on one line; it now says what to try and exits with 2.
- An empty answer from `agy` (headless mode denied a tool it wanted) was reported as a successful, empty reply; it's now a failure that names the denied tool.
- A `claude` worker that exits with an error now shows Claude's own message ("Not logged in · Please run /login"), not its whole JSON report.
- With a fallback order set, a reviewer at its limit could fall back to a worker already in the review, filing two answers under one name; reviews no longer fall back.
- The `claude` worker could never search the web: headless Claude Code denies any tool that would ask for permission, so WebSearch is now pre-approved (`--allowedTools`).
- Isolated tasks corrupted files with CRLF line endings: diffs were read as text, which turned CRLF into LF; patches now move as bytes.
- farmout's own git hook ran a full review on every worktree farmout made; farmout's internal git calls now run no hooks at all (`--no-verify` alone still ran post-commit and post-checkout hooks).
- A worker name in `delegate` could become a path outside the results directory.
- Read-only Antigravity tasks could end with only a plan stub ("please approve to proceed"); the brief now asks for the complete answer.
- The server now stops running workers when it receives SIGTERM, not only on EOF.
- On EOF the server exits at once, even while an `api` request is in flight.
- A JSON line on stdin that is not an object no longer crashes the server.
- `farmout review` mixed up different defects cited on the same or neighbouring lines: findings joined the first group that would take them, so a real run credited codex with a missing-row crash it never reported and inflated agreement counts. Findings are now grouped most-similar first (average linkage over a Dice word overlap), words a model repeats across its own findings (`file`, `quota`) count for little, and light stemming plus a few synonyms (`concurrent` and `race`) match different wordings of one bug. Four real four-model runs, grouped by hand, are regression tests.
- A command given a prompt (`farmout race "..."`, `run`, `ask`, ...) hung forever when stdin was an open socket or device that never closes, as in background jobs of some agent harnesses. Only a pipe or a redirected file is read as piped input now.
- On macOS, stopping a session crashed when `ps` wasn't on PATH; farmout now asks `/bin/ps`, and treats a process it can't check as not its own.
- A turn that finished just as its waiter looked could be reported as "the runner stopped mid-turn": the waiter now reads the turn once more after the runner is gone. CI on macOS caught it.
- With four workers, the review table's "flagged by" column made rows wrap on a 120-column terminal; the findings column now takes only the room the others leave.
- `farmout race` in a repository with no commits listed every worker as FAILED with no reason; it now says to commit first, since each worktree starts from one.
- `farmout bench` left its twelve-odd review sessions in `farmout ls`, pointing at a scratch worktree that no longer exists; it now removes them, and the report keeps the scores.
- A bare `farmout undo` (which `farmout apply`'s own error suggests) was an argument error; it now takes back the last patch applied in the current repository, never one applied in another project. A bare `farmout wait` waits for whatever is running or queued.
- `FARMOUT_CLAUDE_MAIN=1` ignored a `CLAUDE_CONFIG_DIR` set in your shell, so a main login kept outside `~/.claude` ran as the wrong (or no) account.
- In the live lanes, "1 finding" and "2 findings" put the times in different columns.
- `farmout bench` gave the bug away: the diff a worker reviewed also deleted the fix's regression test and changelog line, and the fix itself was the scratch worktree's HEAD commit, so a worker with a shell could read its subject in `git log`. Only the fix's source files are undone now, in a copy whose only commit is "snapshot"; a fix that adds a test file qualifies, and one that changes a template or config doesn't (undoing only its code would half-undo it).
- With no worker ready, `farmout review` printed "No findings", as if the change were fine; review, ask, race, fix-pr and bench now stop and point to `farmout doctor`.
- A review finding that copied the brief's placeholder (`path:163 | high | ...`) cited a missing file and was dropped, though it named the bug. The brief asks for the real path now, and a placeholder path means the changed file when there's only one.
- `farmout fix-pr` treated CI bots' reports (bundle size, benchmarks), the pull request author's own replies and approving reviews as problems to fix, and failed on more than one page of comments.
- An isolated `delegate` result left its worktree and branch behind with no hint; it now names the commands that remove them.
- A cloned repository's `.farmout/pipelines/fix.json` replaced the built-in `fix` pipeline, test command included. Pipeline names now resolve to yours, then the built-ins, then the project's.
- Pipelines: `{item}` in a foreach stage's test, files or workers passed validation but never worked; `workers = "codex"` was read letter by letter; a stage running your skill left the pipeline's own `test` unsubstituted; resuming kept a later stage's approval although its input was about to change; a skill in ask mode failed when one worker did.
- Stopping, cancelling or timing out a worker left children that ignore TERM (or outlive the CLI) running; what's left of the process group is now killed after 10 seconds (3 at shutdown).
- Antigravity sometimes ends with status ERROR after writing its whole answer; farmout discarded the answer, and now keeps it with a note.
- A malformed `notifications/cancelled` (params not an object, a list as requestId) crashed the MCP server.
- When a worker hit its usage limit halfway through an isolated task, the fallback worker carried on from its half-done edits; a worktree the task made is reset to its base first.
- A review finding that cited a file the change deleted crashed the whole review and lost every worker's findings; it's now an invalid finding. An Antigravity write task that ended in ERROR no longer counts as done.
- A turn recorded by a session runner that was then killed could be overwritten by the next turn; turns are numbered after the newest turn file too.
- `farmout bench`: a Django-style `tests.py` counted as source code, so undoing a fix also undid its tests; a fix to a file with a non-ASCII name couldn't be undone (git quoted the name); and one fix that wouldn't undo cleanly ended the run, losing the reviews already paid for. An isolated session's reply told you to delete the worktree its next turn still needs; it now points to `farmout rm`.
- A project's hooks were trusted by hashing the settings file in one read and parsing it in another; both now use one read. Store and skill installs stage in a fresh private folder instead of a fixed `.<name>.new`.
- Python 3.9 and 3.10 couldn't read the settings the leaderboard writes into each copy (TOML needs 3.11); they're JSON now. On Windows, farmout says it needs Linux, macOS or WSL instead of failing on an import.
